## Corrections à faire

1. **Gênant. Une session fermée (compte désactivé) laisse la navigation continuer dans une fenêtre déjà ouverte.**
   - Cas et étape : UC01-06, étape 5.
   - Attendu : après « Désactiver le compte », l'utilisateur ne peut plus travailler ; la désactivation ferme ses sessions (`desactiverUtilisateur` appelle `banUser`, qui supprime les sessions, et le changement de rôle l'annonce : « Ses sessions ouvertes ont été fermées »).
   - Obtenu : dans la fenêtre restée ouverte, un clic sur « Étudiants » ouvre la liste des étudiants avec le nom de la désactivée en bas de la barre (capture `UC01-06-06-clic-apres-desactivation.png`). Un rechargement (F5) renvoie bien vers la connexion (`UC01-06-07`).
   - Cause probable : la session n'est vérifiée que par `requireSession()` du layout `src/app/app/layout.tsx`, qui ne se rejoue pas à la navigation entre pages ; les lectures n'ont pas de contrôle propre (`src/server/lectures/etudiants.ts` ligne 35 : « Lectures sans contrôle de rôle : le layout de /app appelle `requireSession()` »). Seules les pages dashboard, paiements et encaisser rappellent `requireSession()`. Même exposition après une session expirée (12 h) ou fermée dans un autre onglet, tant que la page n'est pas rechargée. Les Server Actions, elles, vérifient la session (non démontré à l'écran).
   - Relais : **backend-builder** (contrôle de session dans les lectures ou les pages de `src/app/app/`, par exemple `requireSession()` dans chaque `page.tsx` ou dans les fonctions de `src/server/lectures/`).

2. **Mineur. Un trop grand nombre de connexions rapprochées est présenté comme un mauvais mot de passe.**
   - Cas et étape : UC01-09, étape 2.
   - Attendu (proposition, le plan est muet) : un message qui dit d'attendre quelques secondes.
   - Obtenu : le bon mot de passe est refusé avec « Adresse e-mail ou mot de passe incorrect. » (capture `UC01-09-02-bon-mot-de-passe-refuse.png`). Better Auth répond 429 après 3 connexions en moins de 10 s (la fenêtre repart 10 s après la dernière tentative acceptée) ; `messageDepuisErreur` renvoie le message d'identifiants pour tout statut inférieur à 500.
   - Relais : **frontend-builder** pour le message sur le statut 429 (`src/components/connexion/formulaire-connexion.tsx`, par exemple « Trop de tentatives. Patientez quelques secondes puis réessayez. »). Voir aussi la question 2.

3. **Mineur. Un nom long rogne le bouton de déconnexion.**
   - Cas et étape : UC01-06, étape 2 (capture `UC01-06-02-haingo-connectee.png`) : avec « RANDRIANASOLO Haingo », la flèche « Se déconnecter » est coupée par le bord de la barre latérale. Le bouton reste cliquable mais mal visible.
   - Cause probable : largeur du bloc nom/rôle dans `src/components/app/menu-utilisateur.tsx` (le nom ne se tronque pas assez tôt).
   - Relais : **frontend-builder**.

4. **Mineur. Menu replié : de petits traits subsistent à droite des icônes.**
   - Cas et étape : UC01-07, étape 3 (capture `UC01-07-03-menu-replie.png`, zoom : un trait par entrée, un point pour « Tableau de bord »). Ce sont probablement les restes des libellés rognés.
